# NASA: требования, источники и неопределённость
Проверка: 2026-11-14. Запрошенная официальная страница https://www.spaceappschallenge.org/2026/challenges/be-an-earth-system-trend-detective/ вернула 502 в инструменте чтения. Альтернативный production slug /earth-system-trend-detective/ также 502. Staging-сайт содержит противоречивый текст об экзопланетах и не принят за нормативный источник. Полная сверка именно официального brief 2026 НЕ завершена; это открытый acceptance item.

По пользовательскому заданию архитектура должна поддерживать: регион/переменную (UI и общий запрос), реальные ряды NASA (backend/nasa, пока spike), тренд/значимость (backend/science, пока Python и parity spike), визуализацию/объяснение (сохранённый Panel). Произвольное усреднение региона не реализовано. Требование конкретно T2M/QV2M, периода, OLS/HAC lag 3 и Vercel — решение команды, не заявляется дословным требованием NASA.

Официальные общие legal terms https://www.spaceappschallenge.org/legal/ указывают свободную доступность оригинального контента либо OSI open-source license. До публичной подачи команда должна выбрать лицензию исходного кода, сохранить third-party notices и цитировать использованные datasets. Самостоятельно лицензия на весь авторский проект не назначена. Нужна проверка правил 2026 Global Judging и списка Resources конкретного задания, включая допустимость выбранного MERRA-2.

NASA-организационный источник https://github.com/nasa/spaceapps/discussions/1849 указывает использование NASA source из challenge Resources для Global Awards и раскрытие AI-generated code/data. Политика проекта: явно раскрыть помощь OpenAI Codex в миграции кода, тестов и документации; научные измерения не сгенерированы ИИ, получены NASA и проверяются по hashes/Python. Человеческая проверка обязательна. Это disclosure не заменяет верификацию окончательных правил 2026.

Цитирование: Global Modeling and Assimilation Office (GMAO), MERRA-2 tavgM_2d_slv_Nx, M2TMNXSLV V5.12.4, NASA GES DISC, DOI https://doi.org/10.5067/AP1B0BA5PD2K ; указывать переменную, исходные/выходные единицы, период, фактическую ячейку, дату доступа, granule IDs и SHA-256. Сохранены manifest и исторический CMR use constraints (3C_NASA_POLICY.json); открытость данных не означает разрешение делиться credentials.

Earthdata server auth: официальная документация https://urs.earthdata.nasa.gov/documentation/for_users/user_token подтверждает user bearer tokens для совместимых приложений (60 дней, до двух действующих). В новом коде токен только server process env EARTHDATA_TOKEN, allowlisted HTTPS host, redirect:manual; нет браузерного секрета, password exchange или токена в Git. Токен не предоставлялся агенту и не извлекался из чужих cookies/netrc.

Правомерность общего серверного Earthdata аккаунта для анонимного публичного сервиса НЕ подтверждена найденными материалами. Нельзя обещать такой доступ. Перед включением public proxy получить подтверждение GES DISC/EDL условий приложения и redistribution, установить лимиты запросов; обращения в поддержку автоматически не отправлялись. При отсутствии подтверждения оставить локальный исследовательский режим с индивидуальным безопасным вводом или заранее проверенные разрешённые производные данные. Авторизация пользователей не добавляется в N1.

## Проверка N3 — 2026-11-14
Официальные EDL user-token docs подтверждают user bearer tokens для совместимых приложений, срок 60 дней и максимум два действующих токена: https://urs.earthdata.nasa.gov/documentation/for_users/user_token . Общая документация разрешает user-level аккаунт для автоматизированного доступа: https://urs.earthdata.nasa.gov/documentation ; welcome описывает доступ application developers: https://urs.earthdata.nasa.gov/documentation/for_users/welcome . Это **не является подтверждением** использования одного личного аккаунта всеми анонимными посетителями сайта. Интеграционные страницы не дали проверяемого разрешения на такой режим; обращения в поддержку автоматически не отправлялись.

Решение N3: shared-account public dynamic заблокирован кодом, в том числе при наличии секрета на Vercel. Реализуется отдельно local-only server access. Срок JWT exp используется лишь как ранняя подсказка истечения, не как проверка подписи; фактическую авторизацию проверяет NASA. 401/403 отклоняют и блокируют повторное использование отвергнутого токена до замены; автоматического password exchange/обновления через пароль нет. Redirect запрещён, TLS не отключается. Пользователь запросил .env и вводит токен сам; файл не читается агентом для вывода, не включается Git, trace или review archive.

Фактическая N3 проверка: local bearer access получил свежие данные для Павлодара, Берлина и третьей ячейки; отчёт N3_LIVE.json. Это подтверждает работу локального механизма, но не разрешение общего personal-account proxy. Публичный dynamic режим остаётся заблокированным.
