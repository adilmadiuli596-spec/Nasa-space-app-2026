# P0 — публичный анализ NASA POWER

## Причина
До изменений production /api/health: mode=blocked, dynamic_nasa_enabled=false. EARTH_MODE по умолчанию blocked; local принудительно блокируется на Vercel; API возвращает public_access_unconfirmed, App.ready разрешает лишь demo/authorized-local. Защита личного Earthdata была правильной, публичного адаптера не было. Зафиксировано в P0_CAUSE.md до изменений.

## Решение
Отдельные src/backend/power/source.ts и analysis.ts; отдельный provenance/result schema для POWER (без выдуманных GES DISC granule IDs/DOI/хешей). Режим power — default, на Vercel обязателен даже при старом blocked/local env. Личный Earthdata не разблокируется. Статистические функции/формулы в backend/science и старый nasa-адаптер побайтово сохранены; единственное изменение в старом nasa namespace — конфигурация режима. Общая loadedSeriesSchema по-прежнему принимает только прежние MERRA-2 данные; output schema дополнена POWER вариантом. Дизайн и переменные T2M/QV2M сохранены, обновлены только состояния и подписи источника.

## Методика и происхождение
Официальная документация: https://power.larc.nasa.gov/docs/services/api/temporal/monthly/ ; правила запросов/разрешение: https://power.larc.nasa.gov/docs/tutorials/service-data-request/api/ .
POWER возвращает T2M в C и QV2M в g/kg, источники MERRA2, LST, API v2.10.0. Геометрия — округлённая запрошенная точка; она не выдаётся за точный центр нативной ячейки. Нативное метеорологическое разрешение 0.5 × 0.625°. Полный JSON-ответ хешируется SHA-256, фиксируются endpoint, публичный URL параметров без credentials, fetched_at, API version, upstream source, native units, cache/direct status.

Из 455 записей каждого параметра берутся только 420 месячных YYYY01–YYYY12; 35 готовых YYYY13 агрегатов не используются. Все 840 месячных значений обоих параметров проверяются: период, источник, координаты, единицы, полнота, finite/fill(-999), физические границы; сообщения качества не игнорируются. Пропуски не интерполируются. Выбранный период агрегируется существующей annualMeans с весами по календарным дням; POWER units адаптируются через прежний canonical unit validator. Существующий hacTrend: OLS intercept, HAC Bartlett lag3, correction n/(n−2), Student t df=n−2, two-sided p, 95% CI. Код этих методов не изменён. POWER — отдельный продукт с округлением/обработкой; его числа не подгоняются под прямой GES DISC эталон.

## Ограничение ресурсов/ошибки
Один запрос забирает оба параметра за весь период. TTL 24h; ограниченный LRU memory cache 4 MiB на экземпляр, без БД/постоянных записей. Single-flight объединяет одинаковые запросы, до 2 работ на экземпляр. Координаты ключа округляются до 5 знаков, существенно тоньше сетки. Между serverless-экземплярами кэш/лимит не глобальные; cold starts могут повторно получить данные. До 2 попыток, 10s на HTTP, общий 23s deadline, максимум 1 MiB; 429 не повторяется, безопасный Retry-After передаётся API. Redirects запрещены, фиксированный NASA origin, никаких пользовательских upstream URL/Authorization. Сбой NASA даёт честную ошибку, а не демо/фиктивный результат. Не подключены платные API/хранилища/биллинг; фактические бесплатные квоты Vercel остаются ограничением.
