# Этап 3C — динамический источник NASA MERRA-2

Дата: 14 ноября 2026. Бюджет проекта: **0 KZT**. Этап выполнен технически, но ожидает проверки пользователя; frontend/3D/Docker не начаты.

## Изменения и устройство

В существующем `backend/` динамический источник подключён через `DataSource` к научному ядру 3B. Реализованы и проверены следующие модули:

| Файл | Ответственность |
|---|---|
| `backend/earth_detective/nasa.py` | CMR-каталог M2TMNXSLV v5.12.4, ближайшая ячейка, месячные DAP4 OPeNDAP подвыборки, проверки NetCDF и происхождение каждой записи |
| `backend/earth_detective/auth.py` | Earthdata auth/session через earthaccess; локальный интерактивный prompt с `getpass`, без persist |
| `backend/earth_detective/nasa_http.py` | HTTPS allowlist, таймауты, повторы 429/5xx, ограничение тела ответа, TLS verify и безопасное преобразование сетевых ошибок |
| `backend/earth_detective/cache.py` | Локальные атомарные JSON-записи, SHA-256, FileLock, повреждённые записи, ограничение размера и истечение каталога |
| `backend/earth_detective/nasa_config.py` | Настройки из окружения, default cache limit 128 MiB, 4 worker, connect/read/analysis timeouts |
| `backend/earth_detective/main.py` | Три сохранённых API endpoint, переключение NASA/reference mode, безопасные ошибки; health не обещает доступность NASA до запроса |
| `backend/earth_detective/source.py`, `result.py`, `schemas.py` | Общий контракт источника, фактическая ячейка, строгий ответ API; неизменённое расчётное ядро 3B |
| `backend/earth_detective/verify3c.py`, `backend/run_nasa.py` | Реальная loopback-интеграция, ошибки, отдельный пустой cold cache и его повтор; только локальный запуск |
| `backend/tests/test_nasa.py` | Тесты NASA-каталога/NetCDF/HTTP ошибок/кэша/конкурентности |

В ходе этой проверки исправлены отображение состояния health при проблеме динамического кэша, устаревший комментарий source-модуля, вводящий в заблуждение прогресс «downloading» для cache hits и добавлен изолированный `--cold-benchmark`. Он не очищает `.data-check` и не удаляет прежний NASA-кэш.

Запрос использует анонимный поиск CMR по продукту, версии и времени; каждый ежемесячный файл читается через CMR-ссылку OPeNDAP с DAP4 constraint только для `T2M`, `QV2M`, выбранных `lat/lon/time`. Полные глобальные NetCDF не скачиваются. Проверяются ровно один месяц и временной индекс, глобальные атрибуты продукта/версии/DOI, размеры массивов, реальные координаты ячейки, исходные единицы, fill/missing, finite/physical bounds. Неполная серия отвергается без интерполяции. Ряд передаётся в существующие days-in-month weighted annual means + OLS + HAC/Newey–West (Bartlett, maxlags=3, small-sample correction, t inference).

## Авторизация, NASA use и конфиденциальность

Использован официальный пакет `earthaccess` (0.19.0) и его поддерживаемый interactive login/session. Учётные данные вводились в локальном PowerShell через скрытый prompt; `persist=False`, username/password остались в памяти процесса и затем были удалены из временных переменных. `.netrc` не создавался. Переменные среды, аргументы процесса, исходники, JSON-ответы API и логи не содержат секретов. Токен не передаётся frontend. TLS certificate verification остаётся включённой.

Подтверждение возможностей и ограничений: [earthaccess authentication guide](https://earthaccess.readthedocs.io/en/stable/user/howto/authenticate/), [NASA CMR search API](https://cmr.earthdata.nasa.gov/search/site/docs/search/api.html), [GES DISC access help](https://disc.gsfc.nasa.gov/help) говорит, что скачивание требует Earthdata Login; [Earthdata Login docs](https://urs.earthdata.nasa.gov/documentation/for_users) описывают бесплатную регистрацию. CMR/OPeNDAP — NASA HTTPS endpoints. Коллекция указывает [NASA data-use guidance](https://www.earthdata.nasa.gov/engage/open-data-services-software-policies/data-use-guidance) и [GES DISC citation guidance](https://disc.gsfc.nasa.gov/data-guidelines); коллекционные metadata/citation сохранены в `docs/3C_NASA_POLICY.json`.

Это подтверждает безопасный локальный single-user сценарий с авторизацией пользователя. Это **не** одобрение публичного hosted-сервиса с одной общей учётной записью Earthdata и не подтверждение публичной квоты/SLA. Backend следует держать локально; публичный сервис требует подходящего per-user NASA auth-потока либо отдельного подтверждения GES DISC. Существуют повторы для 429, но они не заменяют соблюдение лимитов NASA.

## Реальные интеграционные результаты

Продукт: `M2TMNXSLV`, version `5.12.4`, DOI `10.5067/AP1B0BA5PD2K`; по 420 месячных записей и 35 полных годовых средних для периода 1991–2025. Полные JSON-ответы с рядами и provenance сохранены в `3C_API_*.json`; сводка — `3C_INTEGRATION.json`.

| Павлодар 52.27601, 76.96881 | 52.5, 76.875; (285, 411) | T2M, °C | +0.09179457757906843 | 0.5129513990556182 | [−0.1905748233841892; +0.3741639785423261] |
| Павлодар | та же | QV2M, г/кг | +0.17981239344380076 | 0.0023834887902114427 | [+0.06864540028217651; +0.290979386605425] |
| Berlin 52.52, 13.405 | 52.5, 13.125; (285, 309) | T2M, °C | +0.5909734927735855 | 1.1452797118958998e−6 | [+0.3886161100958896; +0.7933308754512813] |
| Berlin | та же | QV2M, г/кг | +0.2185026813732438 | 4.4961594103913643e−8 | [+0.1554869143924395; +0.2815184483540481] |

Павлодарские monthly values совпали со всеми 420 строками `.data-check` в тестовом допуске; оба тренда, p-value и CI совпали с baseline (rtol=1e−10, atol=1e−12). При создании интеграционного ответа все 420 записей Павлодара пришли из уже заполненного проверенного локального кэша (`cache_hits=420`, `network_used=false`), поэтому этот конкретный HTTP-ответ не является новым cold OPeNDAP проходом. Точка Berlin отличалась и ячейкой, и рядом; в первом живом Berlin T2M-запросе было 335 реальных OPeNDAP misses и 85 cache hits. Его 420 месяцев проверены, затем QV2M и повтор использовали тот же кэш.

## Cold/warm производительность

Чтобы не называть смешанный Berlin запрос полностью холодным, выполнен отдельный запрос Berlin T2M с новым пустым кэшем `.cache/cold-benchmark-berlin`:

- холодный API-запрос 1991–2025: **194824.11 ms (194.82 s)**, CMR + 420/420 OPeNDAP misses, 0 cache hits;
- кэшированный повтор: **6211.48 ms (6.21 s)**, 420/420 cache hits, `network_used=false`; ряд и trend идентичны;
- статистический расчёт занял 52.18 ms в холодном запросе и 62.29 ms в повторном; основное время — NASA загрузка/чтение и синхронизация файлового кэша;
- измерение зависит от этой машины и доступности NASA, не является SLA.

Интеграционный Berlin запрос (с 85 прежними hits) занял 163.31 s. Динамический период 35 лет требует нескольких минут холодного ожидания; выгодно показывать пользователю прогресс и кэшировать месяцы по мере получения. Здесь используются 4 параллельных worker и безопасное возобновление уже проверенных месячных записей. Полнота данных и HAC метод не уменьшаются.

## Ошибки и проверки

- В реальной анонимной OPeNDAP-проверке NASA вернула 401; API вернул безопасный `nasa_auth_required` (HTTP 503 для проблемы auth upstream), а не `data_not_available`.
- Неверные координаты дали 422. В тестах проверены внешние 401/403/429/5xx, timeout, TLS failure, connection error, HTML/повреждённый NetCDF, неверные units/time/cell/DOI, fill, некомплект CMR/серии. Эти внешние отказы тестировались через controlled responses, потому что нельзя надёжно заставить настоящий NASA-сервис вернуть 403/429/500.
- Cache tests: повреждение/checksum, контроль схемы даже при пересчитанном hash, byte limit, TTL, 8-thread и 2-process concurrency; повторно скачивается только испорченная месячная запись.
- Полный regression + 3C набор: **107 passed, 0 failed**. Запуск pytest занял 7.54 s; `uv pip check` подтвердил совместимость всех **65** закреплённых distributions.
- SHA-256 snapshot из `3B_INTEGRITY.json` повторно сверил все **446** защищённых файлов `.data-check` и оригинального NetCDF: изменено 0, отсутствует 0. Тесты и NASA кэш находятся только в `backend/.cache`, который исключён из Git.

## Расходы и оставшиеся ограничения

Расходы: **0 KZT**. Использовались уже установленный Python/uv, открытые PyPI packages, NASA open data/HTTPS, локальный CPU/диск; не применялись S3, облако, база данных, карта/тайлы, платный API/ИИ, хостинг, Docker Desktop, billing или банковская карта. Lock содержит 65 пакетов; exact PyPI license metadata и наличие notice/license файла для каждого записаны в `3C_LICENSES.json`. Лицензии бесплатны для локального использования, но при распространении нужно соблюдать notices; в зависимости есть MPL компоненты. NASA citation/use links — выше и в `COST_POLICY.md`.

Проверена только одна точка вне Павлодара (Berlin), плюс Павлодарская эталонная ячейка. Grid logic распространяется на координаты MERRA-2, но полнота/доступность/скорость не проверялись для каждой ячейки. Нет независимой станции для Берлина. Система не оценивает климатическую структурную неопределённость. Health проверяет только готовность процесса/кэша, не доступность NASA. Клиенту нужно показывать текущую ячейку, источник, кэш, предупреждения и сетевые ошибки.

Следующий этап frontend после отдельного разрешения: подключить React к уже существующим endpoint, передавать координаты/переменную/период, отображать месячный ряд/тренд/единицы/ячейку/provenance/cache status/ошибки в утверждённой панели. Необходимо отдельно выбрать бесплатную подложку карты; бесплатность MapLibre сама по себе не покрывает тайлы. Публичный OAuth, 3D-глобус, Docker, push и deployment не входят в 3C и не выполнялись.
