# Архитектура Earth Detective

Дата: 14 ноября 2026. Бюджет: **0 KZT**. В 3B реализованы научное ядро и API, в 3C — динамический NASA-адаптер и локальный файловый кэш. Проверены Павлодар и Berlin; глобальная работоспособность не считается исчерпывающе проверенной. Интерфейс остаётся будущим этапом. Контракты и отчёты — в `BACKEND_3B.md`, `BACKEND_3C.md` и `../backend/earth_detective/schemas.py`.

## Стек и ответственность

| Часть | Технологии | Назначение |
|---|---|---|
| Интерфейс | React, TypeScript | Состояние выбранной точки/периода, панель анализа и доступность |
| Карта и глобус | MapLibre GL JS | Географический выбор, масштабирование, отображение фактической ячейки; совместимость globe-режима проверить на этапе 5 |
| Графики | Recharts | Временные ряды и представление результата в панели |
| Сервер | Python, FastAPI | Валидация запроса, получение NASA, анализ, безопасные ошибки |
| Научный расчёт | NumPy, pandas, SciPy, statsmodels, netCDF4, earthaccess | Чтение подвыборок, проверки, годовая агрегация и OLS/HAC; версии закреплены в `backend/requirements.lock` |
| Локальная интеграция | Docker Compose | Совместный запуск frontend/backend без облачной инфраструктуры |

Библиотека карты отделена от поставщика подложки. Платные тайлы, геокодеры и внешние сервисы не являются скрытой частью MapLibre. Источник подложки выбирается с соблюдением `COST_POLICY.md`; локальные геоданные — предпочтительная бесплатная возможность, ещё не подключённая.

## Реализованный контракт API

| Endpoint | Назначение |
|---|---|
| `GET /api/health` | Проверка процесса; не выдавать здоровье NASA за проверенное, если запрос NASA не выполнялся |
| `GET /api/variables` | T2M/QV2M, названия, исходные и отображаемые единицы, допустимые периоды и ограничения |
| `POST /api/analysis` | Координаты, переменная, период → реальный ряд, тренд, значимость, ячейка, происхождение и предупреждения |

Pydantic-контракт доступен через `/openapi.json`: запрошенные координаты и фактическая ячейка; месячный ряд и годовые средние; тренд, p-value, 95% ДИ и уровень значимости; единицы; метод; источник, продукт/версия/идентификаторы гранул и SHA-256; состояние кэша и предупреждения. `local_verified_reference` обозначает локальный эталон, `nasa_opendap` — динамический NASA-источник. `network_used` показывает фактический сетевой доступ в конкретном запросе. Для одного показателя возвращается его p-value без скрытой поправки Holm. Swagger/ReDoc отключены; OpenAPI доступен.

API поддерживает полные календарные годы внутри 1991–2025, не менее пяти последовательных лет: n > maxlags + 1 для лага 3. Это вычислительный минимум, не гарантия надёжности HAC; для n < 20 добавляется предупреждение. Пропуски отвергаются без интерполяции/удаления. Валидация входа — 422; локальный reference-source отвечает 404 вне эталонной ячейки; динамический NASA сообщает отдельные коды для авторизации/429 (503), таймаутов (504), формата/неполноты (502) и недоступности NASA (503), не маскируя их под отсутствие данных.

## Поток данных

После будущей интеграции UI: клик карты/глобуса → координаты React → FastAPI → NASA-модуль ищет гранулы в CMR → авторизованный подзапрос одной ячейки через GES DISC OPeNDAP или файловый кэш → контроль данных → существующая статистическая методика → результат. Backend/API и кэш реализованы; React-интерфейс ещё не создавался.

Глобус — клиентский способ выбрать те же координаты, а не другой источник измерений. Поздний ответ для прежней точки не должен заменять результат новой точки: отмена запроса или проверка его идентификатора. Нельзя отображать предыдущий результат как ответ для нового места.

## NASA, кэш и безопасность

NASA-модуль вычисляет индексы сетки, запрашивает CMR и ограниченную OPeNDAP-подвыборку; проверяет `time`, `lat`, `lon`, units, fill, продукт и версию. Эталон Павлодара используется только локальным 3B-источником, не как fallback другой ячейки. Реальная динамическая загрузка проверена для ячеек Павлодара и Berlin. Это подтверждает работоспособность вне Павлодара, но не является исчерпывающим тестом всех точек сетки.

Реализованы ограниченные таймауты/повторы, TLS-проверка, атомарная запись, SHA-256/валидация, межпроцессная блокировка и лимит кэша. Earthdata вводится только в локальном скрытом терминальном prompt через earthaccess, без сохранения в `.netrc`; секреты не уходят в браузер и API-ответ. Production/OAuth-поток для публичного сервиса не реализован и не проверен; текущая схема — локальный одно-пользовательский запуск.

Отдельный пустой кэш подтвердил холодную загрузку всех 420 месяцев и точный повтор из кэша; метрики — в `3C_COLD_BENCHMARK.json` и `BACKEND_3C.md`. На следующем отдельном этапе останется UI, карта/глобус и отображение ошибок/происхождения.
