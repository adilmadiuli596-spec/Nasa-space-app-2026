# P0.1 — парные результаты и научный аудит

## Изменения
Первый UI-анализ запрашивает пару через существующий POST /api/analysis с заголовком X-Analysis-Variables: T2M,QV2M. Один loadPower возвращает оба параметра; затем существующий powerResult рассчитывает обе статистики. Ответ содержит results.T2M и results.QV2M. Прежний single-result API без заголовка сохранён.

Frontend проверяет обе переменные, source mode, координаты, период и полноту перед сохранением. В пределах страницы хранится до 8 пар (LRU), ключ — источник/точные координаты/период, без переменной. Выбор переменной меняет только отображаемый результат и не вызывает cancel/reset/API. Смена координат/периода отменяет активную работу, очищает контекст и восстанавливает соответствующую сохранённую пару при наличии; иначе пользователь запускает обычный анализ. Поздний ответ проверяется идентичностью active job и не записывается в другой контекст. Перезагрузка страницы очищает клиентский кэш; серверный ограниченный POWER-кэш P0 сохранён. Дизайн не менялся; в существующей методике уточнено NASA POWER / MERRA-2-derived.

Файлы: src/shared/schemas/pair.ts; backend/power/analysis.ts, services/analysis.ts, services/http.ts, services/catalog.ts; app/api/analysis/route.ts; frontend/api.ts, analysis/pair-cache.ts, components/App.tsx, analysis/Panel.tsx; tests/pair-p01.test.ts; scripts/audit-power-p01.mjs, verify-pair-p01.mjs; этот отчёт/PROGRESS/AGENTS и проверочные JSON/PNG.

## Независимая научная проверка
Два свежих фактических ответа официального POWER Monthly Point API (Павлодар и Берлин, T2M/QV2M, 1991–2025); SHA-256 приведены в P01_SCIENCE_AUDIT.json. В каждом из 4 рядов проверено ровно 420 конечных месячных значений, fill=-999 отсутствует, исходные единицы C и g/kg, 35 полных лет и 9 високосных. Сохранены тесты отказа для неверных единиц/пропусков/качества из P0.

Независимый пересчёт использует обычные нормальные уравнения с неперецентрированным x=year−1991, полную матрицу Bartlett sandwich двойной суммой с lag3, n/(n−2). Student-t p и критическое значение получены адаптивным интегрированием Simpson угловой плотности, без импорта функций aggregation/OLS/HAC/Student из приложения. df=33; t95=2.034515297449337. Импорт powerResult используется только как проверяемая сторона сравнения. Максимальная абсолютная ошибка статистик slope/SE/p/CI — 4.6629367034256575e-15; годовых средних — 1.0658141036401503e-14. Хеши всех файлов backend/science совпадают со снимком начала этапа. Подгонки результатов и Python нет.

## Сопоставление с годовым POWER
[Официальная схема](https://power.larc.nasa.gov/docs/methodology/data/processing/) описывает каскад hourly → daily → monthly → annual и называет годовую операцию Mean of the Months. В этой краткой таблице веса месяцев явно не указаны; она не доказывает равные веса. Приложение сохраняет утверждённое среднее с весами по календарным дням. Мы сравнили его с фактическими YYYY13 и отдельно с равновесным средним 12 месяцев.

Все 140 годовых значений приложения согласуются с YYYY13 в пределах округления ответа POWER до 0.01: максимум 0.004958904109589213 °C или g/kg. Это эмпирическая совместимость с продуктом; внутренние детали вычислений NASA сверх опубликованной схемы не объявляются подтверждёнными. Приложение считает из месячных значений и сохраняет полную binary64 точность, а YYYY13 не использует в регрессии. Равные веса месяцев дают большие отклонения, максимум T2M 0.1324999999999994 °C. Статистика OLS/HAC и p/CI — расчёт приложения, NASA POWER их не предоставляет.
